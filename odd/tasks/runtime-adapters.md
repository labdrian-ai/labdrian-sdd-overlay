# ODD Task — Phase 7: Runtime adapters

> **Roadmap authority:** [Standalone Platform Master Roadmap](../../openspec/decisions/standalone-platform-roadmap.md), canonical **Phase 7 — Runtime adapters**: project Goal/Profile into Claude Code, Codex, OpenCode, Pi; declare tested capabilities, dispatch, cancellation, persistence, restart, authentication, and evidence limits; fail closed or narrow safely where required controls are absent. Linked sources: product P3 (selected reference runtime), product P8 (second-runtime portability), and the historical task alias `runtime-roster` (compared, not merged).

## Problem and why

Every adapter in `engine/runtime` (Claude Code, Codex, OpenCode, Pi) is a configuration and lifecycle projector: install, status, update, uninstall of hooks, manifests, or packages. None projects a Goal or Profile, declares capabilities with evidence, dispatches, cancels, detects authentication, or states its evidence limits in a typed form. Phase 5 deferred the execution of memory plans to this phase, and Phase 6 left a `DependencyProber` that reports everything `unavailable`. Phase 7 connects them for one reference runtime and declares, honestly, what the others do not yet provide.

## Decisions (user, 2026-09-29)

1. **Reference runtime is Claude Code.** Pi uses Claude Code as its model, so it benefits from the same contract.
2. **Dispatch is projection.** The engine never starts sessions. It projects the active workflow (Goal, Profile, current stage) into the session the user already opened, through hooks. Cancel goes through the lifecycle: a paused, abandoned, or closed workflow stops being projected, and while paused the gate denies the tools that would advance it.
3. **No `os/exec` in any new Phase 7 code**, enforced by a static allowlist test modelled on `engine/skills/zero_fetch_test.go`. The existing Pi exception (`pi install`, `pi remove`) stays explicit, bounded, and named in that test. Pi installation is not refactored.
4. **Authentication is detected by presence only.** The prober `stat`s each runtime's known credentials file without opening it and records that the file is present; it never records "authenticated", and the observation states the limit.
5. **Cancel and restart are soft, declared guarantees.** Cancel is a lifecycle transition effective at the next hook event; hard cancel of an in-flight tool is a declared `unsupported` evidence limit. Restart means a new session re-binds to the on-disk workflow at its first `UserPromptSubmit`; the adapter keeps `restart_required` for configuration reloads.
6. **Evidence limits are typed** like `workflow.Observation` (`capability`, `status`, `detail`), and every `supported` or `partial` capability names the test that proves it (engineering default; overturnable at approval).
7. **Claude Code gets the full implementation; Codex, Pi, and OpenCode are declared only.** They receive a typed declaration of what is proven today and an honest `unsupported` for the rest, with the limit written. OpenCode is declared untested because it cannot be tested on this machine. Product P8 (second-runtime portability) stays open and distinct.
8. **The memory plan is projected and enforced only where verifiable.** The session receives the plan (scope, sources, filters, `write: none`). A `PreToolUse` hook denies `longterm-mem query` when its `project` argument differs from the plan's project. What the arguments cannot verify (`get`, which carries only an id; Engram tools; the mapping between plan sources and query sources) is declared as an evidence limit. Writes are never blocked: `write: none` means the directive grants no write, not that writes are forbidden.

## Engineering defaults (parent; user may overturn at approval)

- **New packages.** `engine/capability` holds the typed capability model, the per-target declarations, the evidence guard, and the presence prober. `engine/projection` holds the session binding store, the pure hook decision functions, and the context rendering. `engine/runtime` and `engine/settings` receive wiring only; the CLI lives in `engine/cmd`. The new packages are pure Go over the standard library and existing engine packages; they import no `os/exec`, network, longterm-mem, Gentle AI, or gentle-pi packages.
- **Capability model.** Closed capability set: `installation`, `projection`, `dispatch`, `cancellation`, `persistence`, `restart`, `authentication`, `memory-enforcement`. Closed status set: `supported`, `partial`, `unsupported`. A `supported` or `partial` claim names at least one existing `Test...` function (a guard test scans the engine test files with `go/parser`, no subprocess); a `partial` or `unsupported` claim states its limit. `engine runtime capabilities --target claude|codex|pi|opencode|all` prints the declarations as JSON. Each behavior task upgrades the Claude Code declaration in the same commit that adds its tests, so the guard is green at every commit.
- **Session binding (dispatch).** `labdrian workflow bind|unbind --project <id> --workflow <id>` writes `$XDG_STATE_HOME/labdrian/bindings/<repo-key>.json`, where `repo-key` is the SHA-256 of the git common directory (the root when the checkout is not a linked worktree), so every worktree of a repository shares one binding. Binding files are classified absent/owned/foreign/malformed/unavailable and written atomically, like the workflow store. The git-free HEAD and commondir resolution built in Phase 6 is reused, not duplicated.
- **Hooks.** `gentle-ai-overlay projection hook --event UserPromptSubmit|PreToolUse` reads the hook JSON from stdin and applies pure decision functions of (hook input, binding, workflow state). Output conventions mirror the existing hooks (`engine/gate/gate.go`, `shaper guard-hook`: exit 2 denies). No subprocess, no network, bounded time.
- **Unbound sessions** are a silent passthrough: no output, exit 0, even for malformed input. Any error while a binding exists degrades to allow plus one visible warning, is recorded as an evidence limit, and never blocks the session ("narrow safely").
- **Gate.** (a) While the bound workflow is `paused`, `Write`, `Edit`, `MultiEdit`, and `NotebookEdit` are denied with a reason naming the workflow, `resume`, and `unbind`. `abandoned` and `completed` workflows are unbound on the next hook and never gate. `Bash` is never gated because it cannot be classified reliably. (b) Memory gate on `longterm-mem query`: deny when `project` differs from the plan's project; when the plan has no project (scope `none`) no project is permitted, so every query is denied. Never touches `get`, `promote`, Engram tools, or any write. The matcher covers install-specific tool-name prefixes.
- **Projected context** is bounded (16 KiB), stripped of control characters, and limited to validated identifiers plus the Goal's own fields: workflow id, profile, status, recorded, current, and next stage, the memory plan (scope, sources, filters, omitted filters, `write: none`), the `unavailable` observations, and the declared evidence limits. The plan is `memoryscope.Resolve(DefaultFor(profile), goal project_id, goal_id)`, that is, the profile ceiling; Goal and handoff narrower files are not wired in this phase and that is declared as a limit.
- **Presence prober** implements `workflow.DependencyProber` with `os.Stat`/`os.Lstat` only; a static test forbids `os.Open`, `os.ReadFile`, and `io/ioutil` in its source file. Signals: `credentials-present` for Claude Code, Codex, and Pi; the Engram database file for `memory:engram` (present, not opened); a manual PATH scan for the `gentle-ai` binary (found, not executed, review mode not queried); `memory:procedural-skills` has no check and stays `unavailable`; the longterm-mem signal must be derived by the writer from `engine/runtime/longtermmem*.go` without reading configuration contents, otherwise it is reported `unavailable`. Paths verified today with `stat` only: `~/.claude/.credentials.json`, `~/.codex/auth.json`, `~/.pi/agent/auth.json`, and `~/.engram/engram.db` exist; `~/.labdrian-overlay/registration.json` does not. The `labdrian workflow` CLI switches to this prober; tests keep `UnavailableProber`.
- **Settings.** `engine/settings` gains a `projection` hook family: one `UserPromptSubmit` entry and `PreToolUse` entries (`Write|Edit|MultiEdit|NotebookEdit` and the longterm-mem query matcher), with its own identity token and install, uninstall, status, and drift handling like the existing families. The Claude adapter's status requires the family, so existing installs report `partial` until `install-hooks` is re-run, as earlier families did.
- **Deployment** of the hooks into the user's real `~/.claude/settings.json` is a separate step after merge that needs explicit approval, a backup first, and a Claude Code restart to load the hooks. Tests never touch the real settings.
- **`runtime-roster`** is compared and kept as a linked distinct ID: written when Pi did not exist, none of its tasks applied, and only R-141 (explicit adapter registry) partially overlaps. Its rewrite goes to the deferred cleanup backlog.

## Acceptance criteria

- `engine runtime capabilities --target <t>` prints typed declarations; every `supported` or `partial` claim names an existing test (guard test); Codex, Pi, and OpenCode report `unsupported` for the Phase 7 capabilities with their limits, and OpenCode is marked untested.
- No new Phase 7 code imports `os/exec` or network packages, and within `engine/runtime` only `pi.go` imports `os/exec` (static test).
- Unbound sessions: both hooks are a silent passthrough that never fails, even on malformed input.
- Bound and running: `UserPromptSubmit` injects workflow id, profile, status, current and next stage, and the memory plan within the size bound.
- Bound and paused: file-edit tools are denied with a reason naming the workflow, `resume`, and `unbind`; abandoned and completed workflows unbind and never gate; `Bash` is never denied.
- Memory gate: `longterm-mem query` with a `project` different from the plan's is denied, scope `none` denies every query, a matching query passes; `get`, `promote`, and Engram tools are never denied.
- Restart: a new process re-binds to the on-disk workflow and injects identical state, from any worktree of the repository.
- Unreadable, foreign, or drifted bound state and malformed bindings: nothing projected, one visible warning, no tool denied, an evidence limit recorded.
- The presence prober records `available` only with a stat-level detail, never "authenticated", and its source never opens or reads a file (static test).
- Settings: install, uninstall, status, and drift for the projection family preserve foreign entries byte for byte and are idempotent.
- RA8: the projected context is observed in one real Claude Code session, recorded with the exact prompt count used.

## Risks and points to confirm at approval

- **Session binding** is explicit and stored outside the repository, keyed by the git common directory; there is no guessing from the working directory.
- **The paused gate** blocks file-edit tools for every session of the repository until `resume` or `unbind`; it never blocks `Bash`, reads, or memory writes.
- **Errors never block the session.** "Fail closed" applies where a valid workflow state exists; where it does not, the adapter narrows (projects nothing, warns, declares the limit).
- **Scope `none` consequence:** a session bound to a `standalone-minimal` workflow cannot use `longterm-mem query`.
- **Naming assumption:** the Goal's `project_id` is compared literally with the memory tool's `project`; nothing verifies today that they coincide, so a mismatch produces a denial whose message names both values and the fix.
- **Adapter status** reports `partial` until `install-hooks` is re-run after the projection family lands.
- **Live use** of the hooks requires the separate, approved deployment and a Claude Code restart; RA8 requires per-prompt authorization.
