- **S5 — The parent's spot check.** The proposal (S1): "y yo controlo una muestra contra el código". - **S6 — The precision and where it is recorded.** Scope: a script `tools/review-bench/precision.sh` reads both findings files, the labels and (when present) repro files and prints, per runner side by side (ours and gentle in adjacent columns), overall, per severity, per row (ours `recall`, `hunt`; gentle `review-risk`, `review-reliability`) and per case: the counts `real`, `false`, `unsure`, `not-judged`; precision `real / (real + false)`; and the bounds `real / judged` (every `unsure` counted false) and `(real + unsure) / judged` (every `unsure` counted real), `judged` being all but `not-judged`; and the same counts split by `failure_stated`. The headline precision (L6, L7) leaves `unsure` out and counts a `real` finding whose `failure_stated` is false as false: `real_failure / (real_failure + false + real_no_failure)`, `real_failure` being the `real` findings with `failure_stated` true; it is printed first, beside the count of `unsure` and its two bounds computed the same way (every `unsure` counted false, every `unsure` counted real), and the split by `failure_stated` stays in the output. The Log entry of T4 holds that output, the agreement and control of S5, the cost (launches, relaunches, `not-judged`), and no verdict, since the owner set no bar. `tools/review-bench/README.md` says how to repeat it for a later run set. Acceptance: the numbers in the Log equal the script's output; real + false + unsure + not-judged = 158 for ours and 31 for gentle; the shell tests of T4.
