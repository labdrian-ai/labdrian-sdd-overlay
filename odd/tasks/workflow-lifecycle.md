# ODD Task — Phase 6: Standalone workflow lifecycle

> **Roadmap authority:** [Standalone Platform Master Roadmap](../../openspec/decisions/standalone-platform-roadmap.md), canonical **Phase 6 — Standalone workflow lifecycle**: independently create/start/pause/resume/verify/close workflows without Gentle AI or gentle-pi; cover clean install, restart, corrupt/foreign state, worktrees, missing memory/runtime/auth, rollback/update/uninstall preservation.

## Problem and why

`main` has the declarative pieces — Goal v2 (`engine/goal`), Workflow Profile (`engine/workflowprofile`), Shaper handoff and clearance (`engine/shaper`), the role handoff chain (`engine/roles`), and memory directives (`engine/memoryscope`) — but no workflow *instance*: nothing can be created, started, paused, resumed, verified, or closed, and no state survives a restart. Phase 6 adds that lifecycle as local bookkeeping that works with no Gentle AI, gentle-pi, runtime, memory, or auth.

## Decisions (user, 2026-09-28)

1. **A workflow is its own record** — an append-only, hash-chained event log that *references* one Goal (id + digest), one Workflow Profile (name), and optionally one role chain; it does not reuse the role chain itself.
2. **State lives in the user state home** — `$XDG_STATE_HOME/labdrian/workflows/<project_id>/<workflow_id>.jsonl` (or `$HOME/.local/state/...`), outside the repository, keyed by `project_id` so every git worktree of a project shares it.
3. **Verify is structural** — no execution: chain integrity, Goal digest unchanged, Profile known, recorded stages in Profile order, referenced role chain intact. The `verified` event stores the digests it checked.
4. **Close is explicit and terminal** — outcome `completed` (requires a `verified` event after the last change) or `abandoned` (any time, reason recorded); no event is accepted after `closed`; state is never deleted.
5. **All five profiles work without Gentle AI** — Gentle-dependent review is reported `unavailable`, never approved or silently skipped.
6. **Worktrees** — resolved by decision 2; every event records provenance (worktree root, git HEAD) for audit, not as a key.
7. **Missing memory/runtime/auth never blocks lifecycle operations** — declared dependencies that are unavailable are recorded as `unavailable` observations on the event; the executing adapter (Phase 7) fails closed.

## Engineering defaults (parent; user may overturn)

- New package `engine/workflow`, following the proven `engine/roles` / `engine/shaper` store pattern (XDG resolution with absolute-path checks, atomic temp-file writes, SHA-256 hash chain, fsync). No refactor of the role or Shaper stores in this phase.
- Event record `WorkflowEvent` v1: `version`, `workflow_id`, `project_id`, `seq`, `prev_digest`, `kind` (`created`, `started`, `paused`, `resumed`, `stage_recorded`, `verified`, `closed`), `at`, `provenance`, kind-specific payload, `observations[]`. Strict JSON (unknown fields refused).
- State machine: `created → started → (paused ⇄ resumed)* → … → closed`; `stage_recorded` only while running; `verified` allowed while not closed; `closed(completed)` only if the last non-close event is a successful `verified`; `closed(abandoned)` from any non-closed state.
- On-disk classification when loading (idea taken read-only from `wip/standalone-platform`): `absent`, `owned`, `foreign` (not a workflow log of ours — preserved, never overwritten), `malformed` (unparseable), `drifted` (hash chain broken), `unavailable` (unreadable state home). Only `absent` and `owned` accept writes.
- Overlay install/update/rollback/uninstall must never touch `$XDG_STATE_HOME/labdrian/workflows`; proven by tests.
- Engine never imports longterm-mem or any Gentle AI / gentle-pi package; lifecycle code runs no subprocesses.

## Acceptance criteria

- Each lifecycle operation works with no Gentle AI, gentle-pi, runtime, memory, or auth present.
- A restarted process resumes a workflow from disk with identical state.
- Corrupt, foreign, or malformed state is classified and never overwritten.
- `completed` is impossible without a successful structural verify after the last change; nothing is accepted after close.
- Two worktrees of one project observe the same workflow.
- Overlay update, rollback, and uninstall leave workflow state byte-identical.
- Unavailable dependencies are recorded, never approved or hidden.
