# Changelog

## Unreleased

### Changed

- The `skills` verbs that read their command line with the new strict parser (`list`, `status`, `lint` and `validate` so far; the others as they move, `install` and `add` among them) refuse a flag they do not read, exit 1 with `skills <verb>: unknown flag "<flag>"` and read or write nothing; `list`, `status` and `validate` used to ignore it, `lint` already refused it. The flags the wrapper appends to every verb (`--registry`, `--manifest`, `--source-root`) are still accepted by all of them, a flag written with an equals sign (`--registry=path`) is an unknown flag, and `lint` no longer lets a second path through after an empty first one.
- `skills install` and `skills adopt` name the project, when `--project-id` is not given, by the origin remote of its repository (read from `.git/config` without running git, following a linked worktree to its common directory), and only then by the name of the directory. A checkout whose origin is `github.com/acme/demo` is that project whatever its directory is called, also from a subdirectory or a linked worktree; before, it was the name of the directory. A registry that admits a skill to a project (`install.allowedProjects`) names it by its origin, e.g. `github.com/acme/demo`.
- The skills registry reader dispatches on the file's `version`: a version it does not know is refused first, naming it. A key it does not know no longer refuses the file: it is left out and said on stderr, the verbs that only read go on with the rest, and `skills add` and `skills remove` refuse such a registry because writing it back would drop the key. A field that install, approval or projection depend on (`id`, `path`, `source`, `source.type`, `install`, `install.defaultScope`, `install.allowedProjects`, `install.targets`) is refused, naming the field and the line, when it is not in the shape the reader reads; before, a value on the line of `source`, `install` or a list was ignored without a word.
- Contract frontmatter lists must be inline lists, `[a, b]`. The shapes that were tolerated (no brackets, an unclosed bracket, text after the bracket, an empty value) are now refused with a message naming the key, and quoted items now match.
- The approval record of a skill (`.approval.json`) and the project lock (`.labdrian/procedural-skills.lock.json`) are read strictly: a key that appears twice in any object, and bytes that are not UTF-8, are refused with the word `duplicate JSON object key` or `not valid UTF-8`. Before, the last value of a repeated key won and bad bytes were replaced in silence, so a record could say one thing to the program and another to a person reading the file. The records the program writes are unaffected, and none of the repository's own carries either.
