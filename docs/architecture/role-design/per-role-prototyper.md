## 2. Boundaries (no overlap)
- **prespec-malandra** interviews the human about the problem over the Mom-Test grid and writes no code and no architecture (`skills/prespec-malandra/SKILL.md:14-16,25`).
- **sdd-explore** reads real code and compares approaches without modifying any file (`skills/sdd-explore/SKILL.md:140-142`).
- **prototyper** writes and runs throwaway code in a disposable worktree to measure a premise that reading cannot settle, and returns kill | narrow | continue with numbers (`roles.go:53-56`).
- **shaper** turns the narrowed problem and those measurements into a bounded plan (scope, out-of-scope, stages, tests, risks, estimates) without running anything (`roles.go:60-62`; no Bash, v2 §2).

## 3. Spike mechanics
**Trigger (parent-side, one rule).** Launch the prototyper only when the intake (Goal, prespec brief or exploration) holds a question of one of three shapes: (a) "does installed tool X behave as premise P says", (b) "what is number or threshold N", (c) "can X be done within the appetite" (Shape Up: "Instead of asking 'is it possible to do X?' ask 'is X possible in 6-weeks?'"). Anything else starts the chain at shaper (§4). Each question states the exact premise to test; a question with no premise is returned to the asker, never guessed (same refusal shape as `prespec-malandra/SKILL.md:29`).

**Scratch placement.** The parent runs `git worktree add --detach ~/labdrian-sdd-overlay-worktrees/spike-<goal_id> HEAD` (owner rule: memory/no-worktrees-under-scratchpad.md:15; memory/engram-worktree-project-detection.md:15). Not the platform's `EnterWorktree` nor Agent `isolation: worktree`: both create the worktree under `.claude/worktrees/` inside the repository (EnterWorktree tool description, read in this session), which `.gitignore:32` does not cover. No CodeGraph index there: a spike runs, it does not map, so the per-worktree index rule has nothing to index. The prompt passes the Engram `project` explicitly, because a worktree resolves "unknown" (memory/engram-worktree-project-detection.md:11).

**Throwaway guaranteed by the harness, not by prose.** `--detach` leaves no branch; once the report is persisted the parent runs `git worktree remove --force <path>` and checks that `git status --porcelain` in the main checkout shows nothing but the report path; any commit the spike made loses its only ref with the worktree. The builder re-implements from the report; nothing is cherry-picked (Jeffries at C3: "We plan to throw away the code, although sometimes something is salvaged"; Ricketts: a spike "may start as a SpikeSolution but will continue to grow", c2 wiki `SpikeSolution`, verified).

**Isolation of every command.** `HOME`, `XDG_STATE_HOME`, `STATE_DIR` and `TMPDIR` under one `mktemp -d` directory outside the repository; `LABDRIAN_PI_BIN` stubbed unless the question is about Pi itself, and then only read-only probes (`pi --version`, `pi list`, `--help`) or runs against the temp HOME (memory/tests-touch-live-pi.md:15; the `engine/cmd` `TestMain` precedent, `odd/tasks/shaper-handoff-contract.md:262`). Reference implementations run in a scratch module outside the repository with positive controls (memory/verify-reviewer-findings-against-reference.md:15).

**Time-box and exit.** The question list is closed: one spike per question; a question found on the way goes to `context.open_questions` (`handoff.go:47-51`), never to a new spike (memory/consumer-impact-rule.md:24; memory/one-slice-at-a-time.md:15). The parent sets a wall-clock box per launch (default in §5); the prototyper reads `date +%s` before each run and stops when the box expires or every question has a verdict. Envelope `status`: `success` when every question has a verdict, `partial` when the box expired (existing domain, v2 §2). Per question the verdict is `holds | fails | unmeasured` and the recommendation `continue` (holds), `narrow` (holds only under a condition, which the shaper writes into `out_of_scope`: Shape Up, "call out any cases you specifically aren't supporting") or `kill` (fails, and no narrowing fits the appetite).

**Evidence handed to the shaper.** The payload is `exploration.md` (existing artifact name, `skills/_shared/openspec-convention.md:15,32`; Engram `sdd/{change}/explore`), one block per question: premise verbatim; exact commands with environment and tool versions; raw observed output, bounded; one positive control (a run that must behave the other way); verdict; recommendation; changed-line bucket of the surviving option (§5). Rules: a test the spike wrote is not a verdict (§7); `unmeasured` is never estimated into a number (memory/actuals-instrumentation-capability.md:18); an unrun command is "not run" (core prefix, line 4). The parent records `prototyper -> shaper` with `payload_kind: exploration` and evidence `{kind: report, ref: <path>, sha256}` through `roles append --stdin` (`engine/cmd/roles.go:3-6,247`; `handoff.go:39-43`), spot-checks one recorded command before launching the shaper (the existing parent spot-check rule), and re-runs all of them before delivery when a premise is a third-party version (§1, pi-package-hardening row).

## 4. Chain fit
`roles.go:14-16` says only sweeper and polisher are skippable and `IsValidTransition` (`:131-151`) refuses skipping a mandatory role strictly between `from` and `to`; but nothing precedes the prototyper, and `VerifyChain` accepts seq 1 with `from_role` prototyper **or** shaper (`engine/roles/chain.go:34-41`; "a chain may start without prototyping", `odd/tasks/reusable-roles.md:16`; test `chain_test.go:100`; the workflow lifecycle reuses `VerifyChain`, `engine/workflow/lifecycle.go:484`). ## 5. Estimation skill
The parent sizes the box before launch with `sdd-time-estimation`: a spike is a planning-phase unit, so the bootstrap planning default applies (0.1-0.4 h agent-compute-time, `SKILL.md:41`), Low confidence, 0 checkpoints; default box = its upper bound, 0.4 h, widened only with a stated reason. The prototyper uses the skill's two smallest parts, the changed-line buckets (`SKILL.md:66`) and the decision-gate rows (`:51-59`), to tag each `continue | narrow` option; a measured premise moves the shaper's estimate from "Unknown systems, rules, or data → medium buffer" to "Clear, simple requirement → low buffer" (`:54-55`), for that premise only.

Push, PRs, `gh`: nothing to push from a detached, deleted worktree; said once in the delta.
- `model: sonnet`, as the builder (v2 §2): a spike's value is the measurement, not the code; cost per memory/subagent-prefix-experiment-round2.md:11.
- Delta (4 lines, after the 6-line core):
```
Work only inside the spike worktree the prompt names and write only the report path it names; the worktree is deleted when you return, so nothing in it is the implementation and nothing is committed, pushed, or cherry-picked.
Answer only the listed questions, one spike each, by running the installed tool with HOME, XDG_STATE_HOME, STATE_DIR and TMPDIR under one mktemp -d directory (LABDRIAN_PI_BIN stubbed unless the question is about Pi); a new question goes to open_questions, never to a new spike.
For each question record the exact commands, tool versions, raw observed output, one positive control, and a verdict holds | fails | unmeasured; a test you wrote is not a verdict, and unmeasured is never estimated into a number.
Stop at the time-box the prompt sets (check date before each run) or when every question has a verdict; return kill | narrow | continue per question with the measured numbers, status partial when the box expired.
```

## 7. External practice: only what changed the design
- XP spike (c2 wiki `SpikeSolution`, raw page `c2.com/wiki/remodel/pages/SpikeSolution`, verified-in-source): "Kent dubbed this a 'Spike'"; the code is planned to be thrown away; spikes grow. → §3 deletes mechanically and forbids cherry-picking. `extremeprogramming.org/rules/spike.html` could not be fetched (certificate mismatch; two mirrors unreachable), so its "very simple program to explore potential solutions" wording is inferred from search snippets only; Wikipedia's "Spikes should be timebound and used sparingly" is secondary and adds nothing.
- Shape Up ch. 5 "Risks and Rabbit Holes" (`basecamp.com/shapeup/1.4-chapter-05`, verified-in-source): "technical unknowns, unsolved design problems"; "Are we making technical assumptions that aren't fair?"; "Beware the simple question: 'Is this possible?'"; "call out any cases you specifically aren't supporting"; "Before we consider it safe to bet on, a shaped project should be as free of holes as possible". → question shape (c), the `narrow` → `out_of_scope` mapping, and the prototyper running before the shaper. The chapter names no spike and no time figure, so none is imported.
- Claude Code best practices (`code.claude.com/docs/en/best-practices`, verified-in-source): "Have Claude show evidence rather than asserting success: the test output, the command it ran and what it returned"; "The trust-then-verify gap ... If you can't verify it, don't ship it"; "The infinite exploration ... Scope investigations narrowly or use subagents"; worktrees for isolated sessions. → raw output in the report, the closed question list, a separate context and checkout.
- Agent reward hacking (Baker et al., OpenAI, `arxiv.org/html/2503.11926v1`, verified-in-source): agents learned "modifying functions upstream of the testing framework and unit test files such that tests trivially pass", "exit(0)", "raise SkipTest"; an action-only monitor "achieves only 60% recall" vs 95% for a chain-of-thought monitor. → a spike's success criterion is never a test the spike wrote; the control run and the parent's spot-check are the design's answer, and this repo's own cases (§1, last row) say the same.
- Not imported: SAFe spike stories and point-estimated spikes, and prototype-as-first-draft workflows that keep the code; no evidence in this repo, and the throwaway rule contradicts the latter.
