## 3. Chain and parent duties (runtime-neutral: all through the `labdrian` CLI and one skill)

Order: `[prototyper] → shaper → estimator → builder → [sweeper] → [polisher] → reviewer → delivery`; `reviewer → builder` is the only backward edge (`roles.go:138`). The parent (whatever runtime hosts it) owns:
- **Appends**: `labdrian roles append --stdin` per hop (`engine/cmd/roles.go:3-5`); `payload_kind` = existing artifact names (`exploration`, `proposal`…`apply-progress`, `review-report`, `verify-report`, `archive-report`); estimator hop = two records with the handoff digest (E §5); `partial`/`blocked` envelope → `interrupted` + `resume_reason` (`handoff.go:30-34`).
- **Triggers**: prototyper question shapes (P §3); sweeper T1 (`git diff --diff-filter=DR` + `rg -w` of removed names outside the diff), T2 (`deadcode -test`, `staticcheck`, `shellcheck` delta vs a `mktemp -d` copy of base), T3 (`git status --porcelain --untracked-files=all`) (S §3); readability row when docs/public API/messages/help change (R §2.3); second blind review launch when the Risk line names an item.
- **Worktrees** (never under the repo or the scratchpad, memory `no-worktrees-under-scratchpad`): `git worktree add --detach ~/labdrian-sdd-overlay-worktrees/spike-<goal>` for spikes and `…/review-<head12> <head>` for reviews; removed after the verdict; Engram `project` passed explicitly (memory `engram-worktree-project-detection`).
- **Binding**: parent computes `base`, `head`, `diff_sha256`; refuses a review result whose echo differs; stores it under `odd/review-results/`; delivery recomputes the digest (R §3-4). Reproduction of severe findings by the verifier (or the parent within its 3-call budget) before anything blocks.
- **Persistence**: parent-only for prototyper and sweeper; builder/shaper/delivery keep today's artifact saves (v2 §2 deltas).
- **Home of these duties**: one orchestrator-run skill `skills/role-chain/SKILL.md` within the lint budget (`engine/skills/lint.go:42-44`), `disable-model-invocation: true`, deployed to all three runtimes by the existing skill routes (it is the only runtime-neutral vehicle: the Claude PreToolUse gate and the hook-projected context exist for Claude only, `engine/capability/declarations.go:42-53,204-205` (verified)). If the lint refuses the size, the sweeper trigger splits into `skills/sweeper/SKILL.md` as S drafted; nothing else splits.

## 5. One source of truth, projected (reuse, not a new generator)

Existing mechanism (verified): `engine/gadu` already turns one body (`engine/gadu/persona/body.md`) into three runtime variants with generator-owned frontmatter templates and model constants — `agents/GADU.md` (Claude, `model: opus`, `tools: '*'`), `opencode/agents/GADU.md` (provider-prefixed model, OpenCode schema), `pi/agents/GADU.md` (`model: pi-claude-cli/claude-sonnet-5`, compact body) — with `Generate` (writes) and `Check` (CI drift) and message pins (`gadu.go:4-11,34-98,158-215`; `messages_pin_test.go:19-20`). Deploy today: Claude via manifest `agent` rows; OpenCode via `opencode-agent` rows; Pi via pipkg copying `agents/GADU.md` into the package and `pi_gadu.go` symlinking it into `~/.pi/agent/agents/`.

Design (rungs 4-5: generalize what exists; the new thing is a TOML template, which no copy can avoid):
- Source per role: `roles/<role>/body.md` (core prefix + delta) + the per-runtime frontmatter in one table in the generator (`tools`, `model`, `thinking`), as `gadu.go` keeps its model constants. Generator = `engine/gadu` generalized to N roles (rename to `engine/agentgen`, keep `Generate`/`Check`/pins), emitting `agents/<role>.md` (Claude), `pi/agents/<role>.md` (Pi: provider-prefixed model, Pi tool names `read, grep, find, bash, edit, write, codegraph`, `thinking`), `codex/agents/<role>.toml` (`name`, `description`, `developer_instructions = """<body>"""`, `model_reasoning_effort`; no `model`, see OD3). OpenCode variant not generated (not a runtime in use, memory `agent-runtimes-in-use`).
- Deploy: Claude unchanged (`agent` rows). Codex: add `AGENT_TARGET_PATHS[codex]=$HOME/.codex/agents` (`targets.sh:22-25`) and route `codex-agent` → `capability.TargetCodex` in `agentRouteTargets` (`routes.go:162-165`); rows `codex/agents/<role>.toml managed codex-agent`. Pi: pipkg keeps copying `pi/agents/*.md` into the package (`build.go:141-147` generalized from GADU to the directory); `pi_gadu.go` generalized from one fixed name to every `agents/*.md` in the package, same ownership proof (Readlink equality), same conflict/stale/missing states, same Status lines; `linkGaduAgent` becomes `linkPackageAgents`. The `"agents"` key in the package manifest stays as the overlay's own inventory (harmless; Pi ignores it).
- *Correction (slice 4, 2026-10-22):* the `codex-agent` rows are tagged `custom`, not `managed`: `codex/agents/<role>.toml custom codex-agent`. Every agent file this overlay writes itself is already `custom` (`GADU.md`, `opencode/agents/GADU.md` and the eight role files from `builder.md` to `verifier.md`); `managed` is for the files taken from upstream, which `capture` and `bootstrap` refresh from a deployed copy or a backup and stage only under `skills/ agents/ opencode/`, so a managed generated file could be overwritten by a stale copy and `codex/` is never staged at all.
- Tool-name map per runtime is data in the generator; the exact MCP tool names (Engram, CodeGraph) on each runtime are **tested at implementation**, not assumed (carried unverified fact; gentle-pi drops unknown names silently).
- Rejected: three hand-maintained copies (owner); a shell `for` loop stamping frontmatter (rung 5 but no `Check`, drifts); a brand-new generator package (rung 6: `engine/gadu` already is one).
